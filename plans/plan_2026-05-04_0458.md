## Integration Test Project Plan

### Context

The package has zero tests. I'll create a standard `integration_tests/` dbt project that consumes the package as a local dependency and exercises every materialization. Tests use the `meta={}` Fusion config style throughout.

### Implementation Steps

**Step 1:** Create `integration_tests/dbt_project.yml` — test project config with all hooks wired up, using `dbt_integration_tests` as the target schema prefix.

**Step 2:** Create `integration_tests/profiles.yml` — env-var-based Snowflake connection (account, user, password, role, warehouse, database from env vars, schema uses `dbt_integration_test_<timestamp>`).

**Step 3:** Create `integration_tests/packages.yml` — local dependency pointing to `../`.

**Step 4:** Create source YML (`_sources.yml`) — defines a source table for stream/table tests.

**Step 5:** Create all 23 model files (one per materialization scenario).

**Step 6:** Create all 14 assertion test files (dbt data tests querying `INFORMATION_SCHEMA` or `SHOW` commands to verify objects exist).

**Step 7:** Create `cleanup.sql` macro.

**Step 8:** Create `.github/workflows/integration-tests.yml` CI pipeline.

### Verification

```bash
cd integration_tests
dbt deps
dbt run --full-refresh    # first run - creates everything
dbt run                   # second run - tests idempotency
dbt test                  # assertions on created objects
dbt run-operation cleanup # teardown
```

### Critical Files

- `integration_tests/dbt_project.yml` — hooks, dispatch, vars config
- `integration_tests/models/test_task_root.sql` — task materialization test (most complex)
- `integration_tests/tests/assert_task_exists.sql` — assertion pattern for all tests
- `integration_tests/profiles.yml` — Snowflake connection for CI
- `.github/workflows/integration-tests.yml` — CI pipeline
